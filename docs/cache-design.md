# 目录缓存设计

状态：目录块缓存与提交映射已实现；任务 1–4 的窄检查和任务 5 的受控大记录刷新检查通过。生产包 0.1.2 已更新到真实 ScriptCat；Chrome 156／ScriptCat 1.5.2 实测空树分支为 0 个路径且完整、main 为 58 个路径且完整。真实缓存命中、管理器请求计数、GM 持久化成本、跨版本标签和私有仓库授权仍未通过实机验证；证据见[实现计划](./cache-implementation-plan.md)和[技术选型](./technology.md#本次实现与验证记录)。

## 已确认目标

- 使用脚本管理器的 GM 存储减少重复 API 请求，不引入后端或远程缓存服务。
- 大仓库加载到一半后刷新，可以复用已成功落盘且未被淘汰的目录数据，只请求恢复过程中缺失的数据。
- 继续默认主动预加载，不退回点击目录才加载；目录树与路径查找共用一份运行时索引。
- 用户已选择目录块持久化，并确认取消单条大小门槛、回收重复截断数据及隔离新旧缓存键空间。16 MiB 总逻辑预算是本实现的初始取值，不是用户设定或平台限制。

## 当前实现与验证边界

- `src/storage.ts` 按仓库、scope、SHA 和递归模式保存已校验的 v2 提交映射、目录响应块及需拆分标记；每项响应独立落盘，容量压力时分级回收。
- `src/main.ts` 在线核验仓库 Metadata；公开仓库优先复用提交映射，非公开仓库仍在线解析当前提交以核验 Contents 权限后再访问持久化目录。
- `src/preload.ts` 恢复已落盘目录块，仅为缺失工作调度 HTTP 请求；保留按路径挂载、截断补齐与完整性证明；两个工作槽都包括响应发布等待。
- 任务 1–4 的指定 Vitest 文件与类型检查通过；受控 GM 适配器验证了一条大于 4 MiB、小于 16 MiB 的单键记录可在新预加载实例恢复，刷新不重复请求 Tree。此测试不证明真实管理器已确认写入、物理空间或真实耗时。
- `src/preload.ts` 仅对 Git 规范空树 SHA `4b825dc642cb6eb9a060e54bf8d69288fbee4904` 跳过根 Tree 请求并完成零路径索引；其他 SHA 的 404 仍为失败。对应回归覆盖空树零请求和非空根 404。
- 用户批准后，真实 ScriptCat 更新同一 UUID `05d455de-eb49-4bc6-935c-f4d519f8aa89` 至 0.1.2（enabled）；Chrome 156／ScriptCat 1.5.2 实测空树分支 `0 个路径 · 完整`、main `58 个路径 · 完整`。该验收不证明缓存持久化命中或 manager-side 请求计数。

## 方案取舍

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| 完整索引快照加提交映射 | 小改动即可减少公开仓库同一提交的重复解析 | 加载中途刷新仍丢失进度，不满足本轮目标 |
| 目录响应块加提交映射 | 可复用已下载子树，并从缓存重建未完成的索引 | 需要按块校验、回收与升级隔离；采用此方向 |
| 持久化运行中的任务队列 | 可保存当时排队顺序 | 重复维护调度状态，容易与版本、授权、缓存淘汰脱节；不采用 |

建议以目录响应块作为唯一的持久化目录数据源，不同时写第二份扁平完整索引。完整索引仍在内存构建和复用，阅读状态继续单独保存。

## 缓存对象

| 对象 | 逻辑键 | 内容与用途 |
|---|---|---|
| 提交映射 | `schema + repoId + commitSha + cacheScope` | 保存根 Tree SHA；公开仓库可避免重复解析，非公开仓库不能用它替代 Contents 读取权限核验 |
| 目录响应块 | `schema + repoId + treeSha + recursive + cacheScope` | 保存通过校验的 Tree 响应，包括 `truncated` 与相对路径条目 |
| 需拆分标记 | 与对应递归响应共用键 | 替代已回收的截断递归正文，指示恢复时直接使用非递归枚举；不含目录条目，也不证明完整 |
| 阅读状态 | 保留现有按仓库、ref、授权范围划分的键 | 保存展开、搜索、滚动位置，不承担目录完整性证明 |

- `cacheScope` 沿用现有规则：已确认的公开仓库使用 public，非公开仓库使用当前授权代号；不把 Token 写入缓存键或目录数据。
- 新目录记录、需拆分标记、提交映射及其辅助元数据统一使用独立前缀 `ogt:cache:v2:`。不得把新 schema 记录写入旧前缀 `ogt:data:v1:`，避免仍运行旧代码的标签页将其当作损坏数据删除。
- 必须区分递归与非递归响应。同一 Tree SHA 出现在不同路径时，响应可复用，但须分别挂载到各自路径前缀。
- 提交映射和目录块不因固定分钟数自动过期；版本变化选择新键，容量回收及授权变化负责失效。分支名不能替代实际提交或 Tree SHA。
- 只保存成功且通过结构、SHA 和上下文校验的响应；不把网络、权限或限流错误保存成成功结果。
- 递归截断响应可临时缓存。其条目已被完整目录块覆盖，或预算回收需要腾出空间时，回收该大响应正文，将同一键降为“需拆分”标记，避免与后续子树长期重复存储；当前内存中的条目不因此清除。
- 降级或淘汰的临时条目不保证刷新后逐条重现；仍保留的已完成目录块继续复用。需拆分标记既不是空目录，也不是完整响应。

## 恢复流程

1. 读取并确认 GitHub 页面实际提交；沿用现有页面适配，不猜测分支或版本。
2. 在线获取当前仓库元数据，核对仓库 ID、可见性及 Metadata 访问。Metadata 请求成功不等于 Contents 读取权限仍有效。
3. 公开仓库查找提交映射，未命中才请求提交接口；非公开仓库仍请求当前提交对应的 Git commit 接口，核验 Contents 读取权限并取得根 Tree SHA，再校验或更新映射。任一必要核验失败时，不绕过现有权限边界展示持久化目录。
4. 从当前根树恢复：优先复用完整递归响应；遇到需拆分标记则直接查非递归枚举，缺失时也只请求非递归接口，不重新下载已知截断的大递归响应。临时截断正文仍存在时可先恢复条目，再走同一拆分流程；递归记录缺失而非递归枚举已缓存时直接复用后者。
5. 对子任务重复相同过程，缓存缺失时才发起对应 Tree 请求。响应完成后增量更新运行时索引，并独立落盘该响应块，不等全仓库完成。
6. 通过既有调度规则补齐缺失任务，继续优先当前路径和可见目录。队列耗尽且完整性证明成立后，才进入完整状态。

不持久化请求队列、运行中的 Promise 或 DOM。每次从版本匹配的目录响应重建任务；目录块被淘汰或损坏时，仅相应部分回到缓存未命中。

因此，缓存命中的普通再访仍保留仓库元数据请求；非公开仓库还保留 Contents 读取权限核验。主要收益是省去重复目录请求，不能把提交映射优化误算成所有仓库都能免提交接口。

### 完整性规则

- 完整递归响应可以证明其覆盖子树完整。
- 非递归枚举用于确定直接子项；只有该枚举及所有后代任务均完整，才能证明对应子树完整。
- 截断递归响应的缺失项不能证明文件不存在，仍须走非递归枚举和子树补齐；需拆分标记仅决定恢复路径，不参与完整性证明。
- 非递归响应本身截断时，保留可用数据与不完整原因，不自动无限重试，也不因其来自缓存就改判完整。
- 缓存恢复的部分索引与网络新取得的部分索引遵循同一套完整性规则。

## 写入与容量

- 总计 16 MiB 仅作为脚本自行选择的初始逻辑数据预算，涵盖目录缓存、提交映射、必要元数据和阅读状态；设置及凭据不参与淘汰。该数值不是平台限制。
- 用户已向开发者确认脚本存储没有此前担忧的单条大小限制；新版不再设置 4 MiB 单条门槛，一个目录响应或截断标记保存为一条 GM 记录，不引入分片、多键提交或孤立分片回收。
- 单键记录包含 schema、仓库、授权范围、SHA、递归模式、截断标志及响应条目；标记记录不含响应正文。读取时校验结构与键归属，不合法时按未命中处理。
- 单次 GM 写入确认成功后，才把对应记录视为已持久化。写入失败保留当前内存数据，不误报已落盘。
- 同一键的写入、降级、删除和预算回收通过 GitHub 同源存储锁串行化；锁内不做网络请求。读取遇到并发淘汰可退回未命中，不依赖跨键事务。
- 预算按写后复核与启动回收执行，不承诺瞬时占用绝不超额或物理磁盘已擦除；与既有授权锁的嵌套采用一致获取顺序，避免反向等待。
- 按逻辑记录分级回收：先将递归截断正文降为小型标记，再淘汰普通数据块，最后才在仍超预算时回收非递归枚举和需拆分标记组成的恢复骨架；同级按最近使用排序。恢复骨架也受总预算约束，不永久固定。
- 最近使用信息只作淘汰提示，不作为缓存有效性或完整性依据；读取命中不重写响应正文。
- 单个响应序列化后超出脚本总预算时，只保留内存数据并说明未持久化；没有平台单条限制不等于设备容量无限。
- 合并写入和预算回收不能清除当前运行时索引；缓存淘汰影响以后命中，不应打断当前浏览。

## 调度与授权

- 仓库及所需权限已核验的当前上下文中，缓存命中不计入网络请求批次，也不因目录请求额度不足而阻止本地恢复；实际缺失请求仍受现有约束。刷新后若必要权限核验被限流，仍不能跳过恢复流程中的核验步骤。
- 保留同一次预加载中的请求合并。多个标签页可读取彼此已发布的目录块，但本轮不新增跨标签页网络请求选主；同时首次未命中时仍可能各发一次请求。
- 授权代号变化立即停止旧私有视图与任务；读前、发布前后和破坏性清理时沿用授权复核，旧代号的结果不能进入新视图或新授权缓存。
- 公共仓库变为私有后，不以旧 public 缓存兜底。权限核验失败、凭据失效或被撤销时，不以缓存绕过拒绝访问。
- 不新增定时轮询、自动重试循环或绕过限流的请求。刷新恢复仍有必要的仓库核验请求，不承诺离线或零 API 请求。

## 升级边界

- 新代码只读写 `ogt:cache:v2:` 下的新版目录记录，不再读写旧完整索引；旧标签页可以继续运行旧代码，但两代目录缓存不共享键空间。
- 初次升级允许目录缓存冷启动一次，不转换旧扁平索引。升级或后续回收时，仅删除 `ogt:data:v1:` 下能够解析并确认为旧 `tree` 类型且结构合法的键；删除前复核记录未被替换，并沿用授权锁及授权检查，不按旧前缀整批清空。
- 旧前缀下的 `view` 阅读状态继续使用；设置键 `ogt:settings:v1` 和凭据键 `ogt:credentials:v1` 保持不变。升级不清除它们，正常预算淘汰阅读状态的既有规则不变。
- 旧标签页仍可能重新生成旧目录快照，新版回收需容忍这种情况；两代代码混用期间不承诺全体记录始终处于单版本预算内。旧标签页刷新或关闭后停止旧写入，不为此引入跨版本迁移协议。
- 保留现有路径查找、同上下文切文件、收起、主题及语言行为。本轮不设计新设置页面，也不增加存储容量调节或缓存管理面板。
- 不缓存文件正文，不做离线代码阅读、跨浏览器同步、跨管理器共享或 GitHub 以外平台适配。

## 验收场景

以下为验收目标，不等同全部真实环境已通过。任务 1–4 的指定存储／导航／预加载测试及类型检查已通过；单键超过 4 MiB 的新 preload 实例恢复由一次性受控 GM 测试验证。ScriptCat 安装审批及真实页面刷新、跨标签、权限和请求计数尚未确认。与刷新恢复有关的命中断言均以前一响应已写入成功、版本和授权一致且记录未被淘汰为前提。

| 场景 | 预期 |
|---|---|
| 公开仓库相同提交、完整缓存后刷新 | 使用提交映射和目录块；不重复调用提交解析或 Tree 接口，仍执行必要仓库核验 |
| 非公开仓库相同提交、完整缓存后刷新 | 仍核验 Metadata 和 Contents 读取权限；核验成功后复用目录块，不额外重取 Tree 响应 |
| 大仓库部分完成后刷新 | 恢复已发布响应，只请求缺失目录；不重新请求仍有有效块的相同 Tree 与递归模式 |
| 仅剩缓存非递归根枚举 | 从该枚举及已有子块继续，不先重发根递归请求 |
| 递归及非递归响应截断 | 恢复后仍保持正确的不完整状态；递归正文回收后保留需拆分标记，不重复下载已知截断的大响应；终止性非递归截断不无限重试 |
| 提交或分支切换 | 使用当前实际版本；相同子树可复用，不同版本不会串树或覆盖当前视图 |
| 相同子树挂在两个路径 | 数据只需获取一次，两个路径都正确出现 |
| 响应超过旧 4 MiB 门槛 | 在总预算内按单键保存并可刷新恢复，不再因旧门槛跳过；不合法记录不能产生完整索引 |
| 预算压力下的截断响应与子树 | 优先回收重复截断正文，保留小型恢复骨架和已完成子块；仍超预算才继续分级淘汰，当前内存索引不受影响 |
| 缓存损坏或容量淘汰 | 按缺失路径补取，其余已缓存块继续使用；仅剩需拆分标记时直取缺失的非递归枚举，不退回大递归请求 |
| 存储写入失败 | 当前内存索引仍可浏览和查找，不误报已持久化或保证刷新恢复 |
| 换 Token、清除或跨标签页晚到写入 | 旧私有数据不可读写进新授权；发布、删除及遗留清理无越权残留读取 |
| 多标签页写入、读取与回收交错 | 不把损坏或旧授权记录当作有效数据；设置、凭据不被缓存回收删除 |
| 新旧版本标签页并存 | 新页写入 `ogt:cache:v2:` 后，旧页滚动或导航触发旧回收，新缓存不被删除；新版回收仅清理合法旧 `tree` 键，保留旧 `view`、设置和凭据，旧页继续写入时仍不串键 |
| 首次升级 | 允许一次冷启动，设置、凭据及未被正常预算淘汰的阅读状态保留 |

实现时以窄范围的存储、预加载及导航场景验证上述行为，再在已配对的真实 ScriptCat 环境验证持久化与刷新恢复；受控大仓库场景和真实仓库观察分开记录。
