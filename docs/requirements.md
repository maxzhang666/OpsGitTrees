# 产品需求

状态：首版功能已有代码和生产包；逻辑与浏览器表面验证见 [技术选型](technology.md#本次实现与验证记录)。已在真实 ScriptCat 安装并验证部分行为；真实私有授权及原定兼容矩阵尚未完成，不将功能实现等同于全部体验验收通过。

## 产品定位

做一个面向大众的轻量 GitHub 文件导航油猴脚本，让用户更快地找文件、切文件和找回阅读位置。

出发点是 Octotree 的付费限制与轻量化诉求，而不是复刻其全部功能，也不是另做一个在线 IDE。

初期面向 GitHub。其他平台保留在 [Roadmap](roadmap.md) 中重新评估。

## 目标用户

覆盖公共使用场景，不按发起者个人的阅读习惯决定功能取舍：

- 探索陌生仓库，理解目录结构并查找文件。
- 阅读熟悉项目，在多个文件之间往返。
- 浏览公开项目，或经授权浏览私有项目。
- 在大小不同的仓库中使用同一套基础导航体验。

## 设计原则

1. **不设人为付费门槛**：核心导航能力不划分基础版和付费高级版；真实的 API 限制与授权要求必须如实呈现。
2. **开箱即用**：提供面向一般用户的默认行为，不要求先进行大量配置；公开仓库不强制认证，私有仓库提供可选认证。
3. **轻量不等于等待**：控制请求、内存、依赖与维护成本，不以逐层点击、逐层等待作为默认的数据加载方式。
4. **导航与展示分工**：脚本负责文件导航，文件内容由 GitHub 页面展示，不默认预取代码内容。
5. **少干扰原页面**：侧栏可收起、可调宽，保留正常的浏览器链接行为，避免无必要地改变 GitHub 布局。
6. **状态可信**：树、搜索结果和当前位置与当前仓库及版本一致；未加载完整不能解释为文件不存在。

## 首版范围

以下核心能力已有实现；未完成的真实环境验收在技术选型中单独披露。

| 能力 | 预期行为 |
|---|---|
| 目录树与跳转 | 点击文件在 GitHub 页面加载对应文件，点击目录在树内展开；保留 Cmd/Ctrl 点击与中键打开行为，详见 [交互设计](interaction.md) |
| 默认目录预加载 | 进入仓库即主动获取目录索引，不等用户展开才加载；详见 [目录预加载](directory-preloading.md) |
| 文件名与路径查找 | 在全仓库目录索引中做忽略大小写的文件名／路径子串匹配，结果展示为过滤树；不是代码全文搜索，也不是只过滤已展开节点 |
| 当前文件定位 | 高亮当前文件、自动展开所在路径；提供一键定位，方便滚动浏览后返回当前位置 |
| 阅读状态记忆 | 切文件保留展开状态和树的滚动位置；按仓库与分支隔离，不相互串用 |
| 侧栏控制 | 独立侧栏展开时占用页面空间而非覆盖内容，支持收起、调整宽度并记住设置；GitHub 原生文件树保留不动 |
| 明暗主题 | 跟随页面明暗主题，保证清晰可读，不引入大量皮肤选项 |
| 基础快捷键 | 提供打开／收起侧栏、聚焦查找等少量快捷入口，不建立复杂快捷键体系 |
| 页面状态同步 | 适配 GitHub 站内无刷新导航；切换仓库、分支、文件后同步，不能只在首次打开时初始化 |
| 可选认证 | 未配置 Token 时匿名；已验证并保存的细粒度只读 PAT 默认用于全部 GitHub API 请求，包括公开仓库；不要求注册本项目账号或额外开启公开认证开关；首版不引入授权后端 |
| 状态反馈 | 明确区分加载中、索引不完整、加载失败、授权问题和限流，不能把失败显示为空目录 |

认证是面向公共场景的基础能力，不根据发起者是否使用私有仓库来决定是否纳入。

## 体验验收

后续实现至少需要覆盖以下场景；本节列出验收目标，不代表已完成验证。

- 首次打开仓库，脚本主动启动目录预加载，不需要逐层点击来触发主要的数据获取。
- 索引完整后，展开目录与文件路径查找不再等待目录网络请求；文件跳转仍可由 GitHub 加载内容。
- 从链接直接进入深层文件，可以展开所在路径并高亮；在树中滚远后可以一键定位回来。
- 同一仓库、分支内切文件，展开状态和滚动位置保留；切换仓库或分支，不显示上一上下文的结果。
- 大仓库尚未加载完整时，能够使用已取得的数据，并明确提示查找结果可能不完整。
- 公开仓库无需先配置令牌即可开始使用；遇到平台限流时说明实际限制，而不是引导购买功能。
- 私有仓库缺少权限、授权失效或请求失败时，有对应提示，不伪装成仓库没有文件。
- 收起与调宽侧栏后设置保留；新标签打开和浏览器前进／后退不被脚本破坏。
